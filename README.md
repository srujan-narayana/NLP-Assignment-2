# Project 5: From Static to Contextual

This project compares classical distributional word vectors with frozen BERT representations on UD English GUM. It implements the three Project 5 tasks:

1. Build 100-dimensional PPMI + SVD vectors from a symmetric five-word training context.
2. Train distance and depth structural probes over layers 1–12 of frozen bert-base-uncased, at ranks 32, 64, and 128.
3. Average token representations from the validation-selected syntax layer into static word vectors and compare them with Task 1.

The shared evaluation suite is WordSim-353, the Google analogy set, and a minimum-spanning-tree dependency check over the same 20 GUM test sentences for Tasks 1 and 3.

## Environment

Use Python 3.10 or newer. Dependency versions are pinned in requirements.txt.

~~~sh
python -m venv .venv
# Windows PowerShell
.venv\Scripts\Activate.ps1
# Linux or macOS
source .venv/bin/activate
python -m pip install -r requirements.txt
~~~

The assignment also accepts a Docker workflow. From this directory, one command builds the image, downloads the resources, and runs all three tasks:

~~~sh
docker compose up --build
~~~

The container writes data, checkpoints, results, and the Hugging Face cache to mounted folders. To use an NVIDIA GPU with Docker, run the image with Docker's --gpus all option; otherwise it runs on CPU.

The full experiment needs access to the Hugging Face UD English GUM dataset, the WordSim-353 data, the Google analogy text file, and the bert-base-uncased checkpoint. A CUDA GPU is recommended for Task 2; CPU execution is supported but the complete probe sweep can take a long time.

## Data and model setup

Download the resources and write local CoNLL-U and benchmark files:

~~~sh
python code/scripts/download_data.py
~~~

The default files are:

~~~text
data/
├── ud_gum/
│   ├── train.conllu
│   ├── validation.conllu
│   └── test.conllu
├── wordsim353.csv
└── questions-words.txt
~~~

The code also supports the cached Hugging Face dataset when the local CoNLL-U files are absent. With local data and model caches only, add --local-files-only to the main command. To use another data directory, pass --data-dir PATH; if PATH contains an ud_gum/ directory, the code reads the three split files from there.

## Run the project

Run the complete workflow in order:

~~~sh
python code/main.py --task all
~~~

Run a task independently:

~~~sh
python code/main.py --task 1
python code/main.py --task 2
python code/main.py --task 3
~~~

Task 3 requires Task 1 and Task 2 result files so it can use the selected layer and produce the requested comparison. Run Task 1 and Task 2 first, or run --task all.

For a smaller probe sweep during development, choose a subset of layers/ranks and fewer epochs:

~~~sh
python code/main.py --task 2 --layers 8 --ranks 32 --epochs 1
~~~

This reduced run is for smoke checks; use the defaults for the assignment experiment. Use --device cpu or --device cuda to choose a device. The selected BERT model can be changed with --model-name, but the assignment setting is bert-base-uncased.

## Outputs

- results/task1/task1_results.json: PPMI + SVD metrics and the shared 20-sentence structural check.
- results/task2/task2_results.json: per-layer/rank validation and test scores, plus the selected layer.
- results/task3/task3_results.json and comparison_table.csv: pooled-vector metrics and the Task 1 comparison.
- results/figures/: Task 2 layer plots.
- checkpoints/: vocabulary, SVD matrices, and selected probe weights.
- data/cache/bert/: word-level BERT features stored by split and model revision.

The same saved test-sentence indices are used by Task 1 and Task 3. If a saved sample does not match the current test split size, the run stops with an error instead of silently comparing different samples.

## Tests

Run the deterministic suite from the project root:

~~~sh
python -m unittest discover -s code/tests -v
~~~

The suite covers co-occurrence windows and sentence boundaries, PPMI/SVD edge cases, benchmark evaluation, CoNLL-U parsing, gold tree validation, subword alignment and chunking, probe math/training, online pooling, and a small command-line Task 1 run. The Task 2 extractor is tested with a deterministic local dummy model; that test does not download BERT or stand in for the full GUM experiment.

## Method and reproducibility notes

- Random seed: 42 for SVD, probe initialization/training order, and the shared structural sample.
- Task 1 vocabulary and benchmark tokens are lowercased. The symmetric context window uses original token positions, including when an optional vocabulary filter removes a token.
- Task 2 averages WordPiece vectors back to each UD word. Long sentences are divided at word boundaries so every word retains an aligned representation; no words are replaced with a neighbor's hidden state.
- Distance and depth probes use squared Euclidean geometry and L1 losses, trained with Adam at 1e-3, batch size 20 sentences, for 30 epochs by default.
- Validation UUAS selects the layer/rank; validation depth correlation breaks exact UUAS ties. Test scores are reported per configuration but do not choose the layer used by Task 3.
- Task 3 averages contextual vectors with online per-word sums and counts, so memory use depends on vocabulary size rather than retaining every occurrence.
- OOV benchmark examples are excluded and counted. OOV words in the structural check receive a zero vector; their count is included in the result.

See COMPARISON_REPORT.md for the implementation comparison, design decisions, verified checks, and remaining limitations.
